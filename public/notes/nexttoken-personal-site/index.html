03 / 逻辑

为什么要建，而不只是发朋友圈

四个关键词
概念节目里的含义
GEO / 可抓取平台纷纷反爬，AI 训练爬虫、Personal Agent、搜索爬虫却在全网找信息。自己维护一个对 SEO / GEO 友好的站点，等于给 AI 一个「官方信息入口」——目的不是流量，是「认知」（杨攀第 3 章：「我不需要流量，我需要信息」）。
SSOTSingle Source of Truth。由自己定义「我是谁、做过什么、怎么联系」，避免各平台信息互相矛盾、被 AI 幻觉曲解。企业版本就是把电话、地址、法人拆成最小字段供爬虫索引。
Trusted Network友情链接 = 一种互相认证与背书。只待在单一平台，一旦被误传几乎没有申辩渠道；互相引用让真实内容有互证结构。注意：XFN 关系标记表达的是发布者声明，不是身份认证。
To A服务对象是 Agent。因此除了给人看的页面，还要有 llms.txt、RSS、语义化 HTML，让 Agent 读得懂。
04 / 做法

官方教程还原的六步

照着做即可上线
  1. 一页 HTML：写清「你是谁 / 在做什么 / 有哪些作品」，纯静态、手机可读。
  2. 免费托管：GitHub Pages 或 Cloudflare Pages Direct Upload，二选一。
  3. 独立域名：可选；选愿意长期用的名字，按「首年价 + 两年续费」比价。
  4. 给 Agent 读：/llms.txt、RSS、rel="describedby"、语义化标签。
  5. 友情链接：链接真实欣赏的人，可加 XFN：friend / met / colleague / me。
  6. 加入名录：交给 Agent 发 GitHub PR，审核合并后进入 Web 2.0 Next 名录。

两条托管路线

路线适合谁要点免费边界
GitHub Pages愿意用 Git、想留版本记录建公开仓库 username.github.io → 根目录放 index.html → Settings → Pages → Deploy from a branch（main / root）站点 ≤1GB、带宽软限 100GB/月；公开仓库意味着源文件可见
Cloudflare Pages不想碰命令行本地文件夹含 index.html → Workers & Pages → Create → Drag and drop → Deploy site，直接得 pages.dev 地址拖拽上传 ≤1000 文件、单文件 ≤25MiB；纯静态请求免费不限次
「零成本」的准确含义：免费托管 + 平台免费子域名，不买服务器。独立域名仍需按年付费，官方教程也明确把域名列为「可选、需付费」的第 6 步。节目里说的「每年只花几十块钱」指的就是域名。
补记：Cloudflare 简体中文控制台的入口已改版，实际用词是「计算和 AI → Workers 和 Pages → 添加 → 页面」，见配套上线操作卡。

四条可以直接复制的 Agent 指令（官网原文）

设计上的共同点：先询问、只用你确认可公开的资料、发布前让你确认、未经确认不购买 / 不改 DNS、无法操作账号时改为给出步骤。这一点比最初给的比价建议更严，可直接照用。

① 建站（GitHub Pages）

请阅读 https://web20next.com/github-pages，帮我使用 GitHub Pages 创建个人网站。先询问我的名字、简介、想展示的内容和 GitHub 用户名；只使用我确认可以公开的资料。制作适合手机阅读的静态网站，预览并检查链接。使用免费方案和 github.io 地址，说明公开仓库的要求。发布前让我确认内容和目标仓库；完成后给我实际可访问的网址及更新方法。如果你无法操作账号，请给出我需要完成的具体步骤。

② 建站（Cloudflare Pages）

请阅读 https://web20next.com/cloudflare-pages，帮我使用 Cloudflare Pages 创建个人网站。先询问我的名字、简介和想展示的内容；只使用我确认可以公开的资料。制作适合手机阅读的纯静态网站，输出根目录含 index.html 的可上传文件夹，并预览检查。使用免费方案和 pages.dev 地址，指导我通过 Direct Upload 发布。发布前让我确认内容和目标项目；完成后给我实际网址及更新方法。如果你无法操作账号，请给出具体步骤。

③ 选域名并绑定 与选域名这一步直接对应

请阅读 https://web20next.com/register-domain，帮我为个人网站选择并连接域名。先询问候选名称、后缀偏好、年度预算、现有域名和托管平台。比较 Cloudflare、Vercel 及其他合适注册商的首年、续费和预计三年费用，核实当前价格、隐私保护和 DNS 限制。给出建议供我选择，未经我确认不要购买或修改 DNS。注册后按照托管平台指引协助绑定，保留已有邮箱等记录，检查 HTTPS，并说明续费设置。如果你无法操作账号，请给出具体步骤。

④ 把网站提交到共享名录（join 页）

请访问 https://web20next.com，帮我把我的网站分享到这里。
我的网站是：[填写你的网站地址]
只使用我确认可以公开的资料。

提交链路：Agent 读 /llms.txt 拿到贡献规则 → 整理 sites/<slug>.json → Fork 仓库、开分支、跑校验 → 发 Pull Request → 自动检查 + 维护者人工审核 → 合并并部署到 Cloudflare → 名录、首页、RSS、directory.json 同步更新。「已提交 PR」「已合并」「已上线」是三个不同状态。

05 / 样板

活样板：qiaomu.ai 是怎么做的

结构可直接借鉴

向阳乔木本人的站就是这套主张的实例：

  • 一句话身份锚点：「做更多事，让更多人知道」+「前字节跳动商业化 AI 产品经理，《AI领导力》合著者」，紧跟一句说明自己把工作流做成工具、写成笔记、录成播客。
  • 可核验的数字：107 个上线网站与开源项目、010 期播客、10,954 颗 GitHub Star——用事实而非形容词建立可信度。
  • 三栏内容流：最新博客 / 播客 / 乔木 AI 资讯，每条都带日期与外链；另设 Projects 作品墙与 Friends「乔木推荐」友情链接板块。
  • 子域名矩阵：blog.qiaomu.ai、rss.qiaomu.ai、airss 等，把一个主域名沉淀成一个人的作品索引。
对照可见：节目讲的不是「做一个漂亮主页」，而是把个人网站当成自己控制、持续更新、可被人和 Agent 引用的事实源。
06 / 衔接

和「申请域名」这一步的衔接

从研究到落地
  1. 两边结论一致。官方域名教程优先推荐 Cloudflare Registrar（成本价、与 Pages 同控制台）与 Vercel Domains，与此前给的个人/学习用途建议吻合；差异是官方还提醒 Cloudflare 注册的域名必须使用 Cloudflare nameservers，但网站仍可托管在 GitHub Pages，只需在 CF 配 DNS 记录。
  2. 比价口径也一致。官方建议用「首年价 + 两年续费」估算三年成本，别只看首年促销；并点名 Premium 域名、隐私保护、自动续费三个坑。查到 2026-11-01 起 .com 上游批发价上调、阿里云涨到 ¥90/¥99，正是这个逻辑的现实背景。
  3. 顺序建议：先上线，后绑域名。用 github.io 或 pages.dev 免费地址先把「一页介绍」发出去，域名到手后再绑定，官方明确说「不需要重新建站」。这样域名没定也不耽误开始。
  4. 备案提醒：若用大陆服务器需 ICP 备案；GitHub Pages / Cloudflare Pages 属境外托管，不需要备案。国内注册商买域名需个人实名，海外注册商不用。
  5. 补记（发布时）：简报写成时域名字符串尚未给出，WHOIS 可注册性与各后缀报价待查；此后本站选定 hilltoken.net，走 Cloudflare Pages 路线上线，并同时绑定 www.hilltoken.net。第 ④ 节的「加入名录」与 GitHub 源码仓库尚未做，不影响站点可被访问、可被读懂、可被引用。
